# 实现与数据布局

启动器源码使用 Java 17 标准库，无 Maven/Gradle、JNI 或第三方 JAR 依赖。业务逻辑独立实现，界面只输出终端文本。

## 启动链路

1. `Main` 处理全局参数并锁定显式的数据目录。
2. `Shell` 将指令解析为自有 argv，执行 `;` / `&&` 链，不调用系统 shell。
3. `Minecraft` 解析父子版本，按操作系统与 feature 规则筛选库和参数，构造共享下载。
4. `Sources` 按所选下载源映射元数据、客户端、库、资源及 Java 地址；默认官方源限制为 Mojang 域名，自定义源默认使用 HTTPS，局域网 HTTP 需要显式启用并限制在配置范围。登录请求不经过下载源路由。
5. 下载先校验已有文件，读取 `.part` 断点，校验 Content-Range、大小和哈希，最后原子提交。
6. `JavaRuntime` 选择游戏所需 Java。`Accounts` 在真正启动时刷新需要刷新的登录。
7. `Launch` 提取本地库、准备旧版虚拟资源、生成独立参数数组，避免把含空格路径拆开。
8. 独立 Java `GameWorker` 从匿名标准输入管道接收参数和令牌，不把令牌写进临时票据。
9. 监护进程执行显式的前置命令，启动游戏，持续写入脱敏日志，保存 PID、创建时间与退出码。
10. `stop` 校验 PID 的开始时间以避免误杀已经复用 PID 的其他进程。

## 数据目录

```text
cairn-data/
  config.json                 非私密全局配置
  accounts.enc                AES-GCM 账户与刷新令牌
  secrets.enc                 AES-GCM 资源 API 密钥
  vault.key                   当前用户权限保护的本地密钥
  .lock                       单目录单启动器锁
  history.txt                 过滤敏感指令后的终端历史
  minecraft/
    versions/                 共享版本描述与客户端
    libraries/                共享库
    assets/                   索引、对象、日志配置、旧版虚拟资源
    shared/                   显式关闭隔离时的数据目录
  instances/<ID>/
    instance.json             版本、加载器、描述、收藏、实例覆盖设置
    content-lock.json         由资源安装器管理的文件、哈希、版本和来源
    game/                     Mod、配置、世界、资源包等隔离数据
    natives-<os>-<arch>/       已提取本地库
    backups/                  部分配置编辑前的备份
  runtime/                    Mojang 官方 Java 运行时
  cache/                      元数据、安装器和临时工作区
  logs/                       游戏、加载器和联机日志
  sessions/                   游戏监护状态
  trash/                      回收内容及恢复路径记录
```

同一数据目录不能被两个启动器进程同时修改。独立游戏监护写自己的会话和日志，不占用启动器目录锁，因此重新启动终端后仍可查看/停止游戏。

## 账户协议

微软设备代码授权使用公共客户端流程。授权后依次执行 Xbox RPS、XSTS、Minecraft token exchange、所有权检查和 profile 获取。刷新令牌保存在凭据库中，启动时接近过期会刷新。客户端 ID 和 CurseForge Key 均不借用其他启动器的秘密。

Yggdrasil 实现 authenticate/refresh，并使用账户的 selected profile 和可选角色选择。实际游戏认证通过使用者提供的 authlib-injector 完成；不包含该工具的二进制文件。

离线 UUID 依据 Java 常见离线玩家命名规则构造。离线登录不会绕过在线服务器的认证。

## 下载边界

默认只启用 Mojang 官方清单及官方文件域名，没有预置第三方镜像。自定义源存放在配置的 `sources` 映射中，`source` 是当前源 ID。支持完整清单 URL 与各类下载基础地址分别覆盖；保留原始 Mojang 路径，兼容路径前缀可由使用者配置。

不同源及不同源配置的元数据缓存使用独立指纹，避免切换后读到旧源清单；共享文件仍按哈希复用。修改源时要求后台任务结束。配置导入对源定义和选择做原子校验，避免留下不存在的当前源。

所选元数据中的哈希用于文件一致性检查。镜像本身的信任不能仅靠它自己提供的哈希建立。自定义源允许 HTTPS CDN 地址；显式允许的 HTTP 仍受配置的主机、端口和路径约束。加载器、社区资源和账户服务各自独立，账户凭据不会转交给下载源。

哈希优先使用上游提供的 SHA-1、SHA-512 等。某些加载器索引的个别条目没有哈希，只能依赖 HTTPS 和实际流传输完成；不能把这些文件表述为均经过独立哈希认证。

不关闭 HTTPS 证书验证，不把认证头转发给不同主机的重定向目标。速度上限模式使用单工作线程，避免多个线程各自达到上限而超过总限制。

## 输入、归档和恢复

自有脚本不会隐式执行 OS shell 命令。显式配置的 before/after 是进程 argv，按用户指定执行。整合包导入只采纳有限的显示/内存配置，不接纳其中的可执行钩子。

文件 ID、Maven 路径、ZIP entry 和下载输出经过路径约束。拒绝越界、符号链接、Windows ADS/设备保留名及重复归档路径。解压限制条目数、单文件大小和总展开大小。导入先创建临时实例，成功后提交，失败实例和临时提取区移入回收区。

共享库/同 ID 版本冲突时拒绝静默覆盖。移除实例、资源和缓存使用可恢复的移动。回收记录恢复时重新验证目标位于自己的数据目录、目标尚不存在。

这些措施不是对恶意 Mod 的沙箱：Minecraft 和 Mod 是本地可执行 Java 代码，会以当前用户权限运行。

## 字符交互和跨平台边界

使用 Unicode/ASCII 边框，按中文字符宽度排版，外部元数据和游戏日志去除终端控制序列。提供纯文本与 JSON 输出。无需图形工具包初始化。

Windows x64 已执行构建、下载、实例管理和监护夹具测试。Linux/macOS 的平台规则和代码分支存在，但本次没有可用对应系统完成实际验证。PCL 的原生 Windows 窗口操作、私有节点和特例兼容补丁不因采用 Java 就自动具备。
